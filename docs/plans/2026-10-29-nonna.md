# CHS NONNA gridded bathymetry (Canada, 10 m and 100 m)

## Goal

Ingest CHS NONNA-10 and NONNA-100 as two DEM sources in the mosaic, so Canadian coasts, the Canadian Great Lakes, and Arctic shipping corridors get surveyed depth on Chart Datum, the low-water datum the chart wants, with no offset grid. NONNA is a gridded product (32-bit GeoTIFF, BAG, CSAR), not just points. Its coverage follows the survey record, so it is sparse, but it is the same kind of input as AusSeabed or UK multibeam. Feeding NONNA into the soundings layer ([#44](https://github.com/openwatersio/seascape/issues/44)'s framing) falls out for free, because soundings are selected from the merged DEM.

## Product facts

Verified 2026-10-29 against the [open.canada.ca record](https://open.canada.ca/data/en/dataset/d3881c4c-650d-4070-bf9b-1e00aabf0a1d) (data updated 2026-04-01) and live requests.

| | NONNA-10 | NONNA-100 |
| --- | --- | --- |
| Native grid | 0.0001° (0.0002° lon at 68–80°N, 0.0004° north of 80°N) | 0.001° (same latitude steps) |
| Index cells | 72,305 cells of 0.1° (0.2–0.4° wide north of 68°N), 17,667 of them north of 68°N | 1,220 cells of 1° |
| WCS coverage | `nonna__NONNA 10 Coverage`, EPSG:3857, 19.11 m px (the z13 grid exactly) | `nonna__NONNA 100 Coverage`, EPSG:3857, 152.9 m px (the z10 grid) |
| Max zoom | z13 | z10 |

- Horizontal datum is WGS84. The vertical datum is CHS Chart Datum (LLWLT on the coasts, IGLD85 low water datum in the Great Lakes). Values are elevations: seafloor negative, drying heights positive (observed max +9.5). No `negate` and no `datum_offset_m`.
- The WCS at `https://nonna-geoserver.data.chs-shc.ca/geoserver/wcs` is public and documented on the open.canada.ca record, and it needs no account. `GetCoverage` with `subset=X(..)&subset=Y(..)` in EPSG:3857 metres returns Float32 GeoTIFF with nodata 3.4028235e+38. It honours `scaleFactor` (`scaleAxes` returns 404) and the GeoTIFF extension's `geotiff:compression=DEFLATE`.
- A malformed request returns HTTP 404, so `http_download` raises and the fetch fails loudly. An area with no data returns a valid all-nodata TIFF.
- The tile indexes are public shapefiles: `NONNA10.zip`, `NONNA100.zip` and `NONNAP10.zip` (1° package cells) under the record's attachments. The attachment proxy serves no byte ranges, so they are downloaded whole.
- The portal at data.chs-shc.ca serves native tiles and 1° "P10" zip packages through a guest-token API. That API is undocumented, so this source does not use it.

## Approach

Two sibling sources, `sources/nonna_10` and `sources/nonna_100`, each only `metadata.json` and `file_list.txt` (WCS `GetCoverage` URLs). The engine names each raw by URL hash and fetches items independently with retries, so a long pull resumes per item. [scripts/nonna_harvest.py](../../scripts/nonna_harvest.py) regenerates both lists from the public index. It lives outside the source dirs because every file in `sources/<id>/` feeds the recipe hash, and raws are temp, so any recipe change refetches the whole national pull. It refuses to shrink a list unless run with `--allow-shrink`, and its bbox mode prints URLs instead of writing.

### Request units

- **NONNA-100:** one request per 1° index cell, 1,220 URLs.
- **NONNA-10:** one request per 0.5° bin that any index cell overlaps, 5,503 URLs. Arctic cells are 0.2–0.4° wide and cross bin edges, so a cell lands in every bin it overlaps.
- **Compression:** requests ask for DEFLATE GeoTIFF. Values are identical to the uncompressed response. A dense Fundy bin (77% valid) drops from 50.5 MB in 82 s to 25.8 MB in 30 s. A near-empty bin drops from 77 MB in 53 s to 171 KB in 8 s.
- **Arctic:** the WCS grid is a fixed 19.11 m in Web Mercator, about 5 m on the ground at 75°N, while NONNA's native cell there is about 11 m north–south. Bins whose south edge is at or above 68°N request `scaleFactor=0.5`: 2,535 NONNA-10 bins and 400 NONNA-100 cells. On a 75°N cell this cut request time from 7.2 s to 2.8 s.
- **Prepared size:** the four Fundy 0.5° bins (33–98% valid) prep to 98 MB of ZSTD COGs. Prep takes about 2 s per source.

### Build size

The covering registers each file's bounds, not its data, so every 0.5° bin raises its z8 stems to the bin's zoom however sparse the bin is. Computed from the lists:

| | z8 stems touched | at child zoom | child tiles |
| --- | --- | --- | --- |
| NONNA-10 | 2,837 | 882 at z13, 1,955 at z12 (Arctic, scaled) | about 1.40M |
| NONNA-100 | 3,318 | 964 at z10, 2,354 at z9 | about 25k |

Against every other source's published file bounds (child tiles at each file's zoom), production is about 2.82M child tiles. NONNA-10 alone is about 1.40M, the same order as NOAA S-102 (1.34M). Net of tiles other sources already raise, it adds about 1.30M (+46%): 0.80M south of 68°N and 0.51M in the Arctic, where many bins are a few percent valid. NONNA-100 adds about 22k. The WCS pixel is 0.056% finer than the Web Mercator zoom grid (19.0986 m against 19.1093 m at z12), so every file resolves to the finer zoom with a 0.01–0.17 m margin: NONNA-10 to z13 (z12 scaled), NONNA-100 to z10 (z9 scaled), never tying GSC Atlantic at z9 or GEBCO at z8.

### Footprint

`source_polygonize` coarsens each mask to about 100 m (`COARSEN_TARGET_M`), then sieves holes and islands under 16 mask pixels (`SIEVE_PX`). On the Fundy cell the sieve takes NONNA-10 from 105k to 25k vertices and NONNA-100 from 93k to 39k, losing 1.5% of footprint area. Filling holes alone barely helps (105k to 104k), because NONNA's speckle is small data islands. A file whose data is all sub-sieve speckle keeps its unsieved mask, so no file loses its footprint. Footprints feed only the z8 coverage layer; the covering uses file bounds, so a sieved island never drops data from a build. Every source picks up the sieve the next time it re-polygonizes.

### Precedence

Merge order is `priority` DESC, then maxzoom DESC, then source id ascending. The coverage layer carries `source_priority`, so click-to-identify names the source the build used.

- **NONNA-10 has `priority: 1`.**
  - **CUDEM** (z13, NOAA VDatum → MLLW) reaches into Canadian Fundy waters around Grand Manan. VDatum stops at the border, and the datum grid's outward fill is what puts CUDEM on "MLLW" there. Over about 7M overlapping pixels, CUDEM reads shallower than NONNA by a median of 0.5–2.6 m (p5 −4.0 m, p95 up to 9.2 m). With priority, NONNA wins. In the Grand Manan stem 14.9% of water pixels changed, median 1.67 m deeper, concentrated in Grand Manan Channel and south of the island. CUDEM still fills NONNA's gaps, so gap edges there mix the two datums. S-102 (priority 1, z14) still wins where it reaches.
  - **GSC Pacific** (10 m, z13, LLWLT, continuous) loses to NONNA-10 wherever NONNA has data. Both are on CHS Chart Datum, and GSC Pacific fills NONNA's gaps.
- **NONNA-100 has no priority**, so its 150 m cells never override a finer source.
  - **GSC Atlantic** (100 m, z9, no stated datum): NONNA-100 wins on zoom. This is the main gain offshore, since GSC Atlantic has no single correct datum offset.
  - **NCEI Great Lakes** (~90 m, z10, LWD) ties with NONNA-100 and wins on id. NONNA-10 still wins in the Canadian halves wherever it has data.
- **GLDB** (priority 1, about 930 m) beats NONNA-100 inside GLDB lakes such as Lake Winnipeg; NONNA-10 still wins there where it has data. GLDB is superseded only for lakes another source covers whole, and NONNA covers these only in part.
- **Sign check:** with priority, NONNA-10 reads deeper than CUDEM over Grand Manan (median 1.67 m, p95 above 7 m). CHS Chart Datum (LLWLT) sits at or below MLLW, which should make NONNA read shallower, not deeper. So the difference is more likely CUDEM's extrapolated datum or different source surveys than the datum definitions themselves. Worth a look before building wider, since the chart errs shallow everywhere else.
- **`land_clamp`** stays unset. NONNA carries drying heights, which the drying layer wants. The Fundy preview showed detailed drying banks in St Mary's Bay and no seams.

## Steps

1. **Website:** render each source's `notice` on openwaters.io/charts/seascape (openwatersio/website, `website/src/pages/charts/seascape.astro`). Land it before the first build that includes NONNA.
2. **First ingest:** merging adds both sources to the weekly sources cron, which runs every source with no filter. Merge, then dispatch the sources workflow filtered to `nonna_100`, then to `nonna_10`, before the next Monday cron. Each dispatch needs explicit approval. `fetch_item` has no per-host limit, so the dispatch's `--cores` sets the request concurrency against the CHS GeoServer; watch the first minutes for 5xx or throttling. All of a source's raws sit on the store volume until its single prep job runs.
3. **Build:** dispatch a build after both sources register.
4. **Close #44:** rewrite the issue as this source and point its soundings framing at the existing soundings layer. Editing the issue needs approval.

## Known limitations

- Editing anything in `sources/nonna_*/` (the notice, licence or priority) re-preps that source, and raws are temp, so it refetches the whole pull from CHS.
- The coverage layer's sieve fills sub-0.16 km² gaps and drops islands of that size, so click-to-identify can name the wrong source on those spots.
